Action placement: collection header

The create action sits right after the title of the collection it creates into, never in the page header's corner; the count and secondary actions trail. On a board or table it follows the filter that scopes it. The page's one create button answers c; an empty collection repeats it as a secondary button. Tag input: multi-select combobox

Pick several values from a known vocabulary: chosen values are chips with a remove button, typing filters the rest (label and aliases, case-insensitive), ↑/↓ and Enter add, Backspace on an empty field removes the last chip, Esc closes. Use it instead of a checkbox grid once the vocabulary outgrows a handful of options. Built by dist/tag-input.js (dakitTagInput.create). See docs/tag-input.md.

Segmented control

The one look for view switchers and list filters (docs/segmented.md): a track of segments, the selected one in the kit selection. Pick the semantics by what it does: route links use aria-current, in-page views a tablist, a single-choice filter a radiogroup. Arrow keys move the choice in the last two. Too many segments scroll inside the track; they never wrap.

Loading data for a dialog

A dialog that needs data opens only when the data is in (docs/dialog-loading.md). Until then the trigger is busy: same size, spinner after 150ms, a second click ignored. Past 500ms the dialog backdrop appears with a centred spinner; Escape or a backdrop click cancels. A failed load opens nothing and shows a toast with Retry. A row has no room for a spinner, so it gets the overlay at 150ms.
